Bedrockサーバーの「Unsupported Transport / Error 149」の直し方

Minecraft Bedrock Dedicated Server（BDS）で接続時に Unsupported Transport / Error 149 が発生する場合、2026年10月29日からのネットワーク移行が関係している可能性があります。Microsoft/Minecraft公式案内によれば、従来のRakNetからNetherNetへの変更が始まりました。

まず確認すること
  1. サーバーを BDS 26.60以降に更新する。ワールドと設定は更新前にバックアップする
  2. server.properties に transport=nethernet を設定する
  3. server-port=19132 を確認し、ルーターからサーバーへの TCP 19132 の転送と、ホストの受信TCPルールを確認する
  4. UDPの送信と戻りの通信をファイアウォールとルーターが許可しているか確認する
  5. サーバーを安全に停止・再起動し、別回線から接続テストする
server.propertiesを無料で編集する

1. 現在のサーバーバージョンを確認

新しいクライアントを使用している場合、古いBDSでは接続互換性がありません。BDSを停止して、worlds、server.properties、allowlist.json、permissions.json、keys を含めてバックアップしてください。その後、公式配布元から対応するBDSの最新版を取得します。既存ワールドを新しい形式に更新した後のダウングレードは避けます。

2. server.properties のNetherNet設定

次の例は一般的な接続に関連する箇所です。既存ファイルの他の設定を丸ごと上書きしないでください。

transport=nethernet
server-port=19132
online-mode=true

server-ip は特定のネットワークインターフェイスに固定する必要がないなら空欄にしておきます。インターネット公開時は online-mode=true を維持してください。

3. TCPとUDPの違いに注意

公式手順は、通常の家庭内ネットワーク向けに TCP 19132 のポート転送、サーバーPCのTCP受信ルール、そしてUDP送信・戻り通信の許可を案内しています。NetherNetではUDPゲーム通信にOSが選ぶ動的ポートを利用できるため、すべての環境で固定UDPレンジの転送が必要なわけではありません。

厳格なNATやファイアウォール環境でUDPポートを明示的に管理したい場合だけ、公式ドキュメントに従い server-udp-ports を設定し、ホストとルーター両方の設定を一致させてください。

# UDPポート固定が本当に必要な場合の例
server-udp-ports=49152-49200

外部へポートを開放するとホストがインターネットからアクセス可能になります。必要最小限の公開にとどめ、OS/BDSを更新し、許可リストや認証を利用してください。

4. まだつながらない場合の切り分け

同じLAN内で接続できるが外部回線からだけ失敗する場合は、ルーターの転送先IP、二重NAT、CGNAT、ISPの制限を確認します。LAN内ですらつながらない場合は、BDSの起動ログ、正しいホストIP、クライアントとBDSのバージョン、Windows/Linuxのファイアウォール設定を確認します。

コンソール端末からの接続では、ゲーム機側がカスタムサーバー追加機能を表示していない場合があります。Microsoftのサポート対象外の接続回避策を前提にはしません。

BDS移行・接続トラブル調査（有償）

環境ごとの起動ログ、ネットワーク設定、BDSとクライアントのバージョンを整理して再現・原因調査を行います。基本構築の参考料金は6,000円〜。調査範囲と価格は事前合意、修正可能かは環境によります。
