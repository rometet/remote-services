1. server.propertiesとは？　どこにある？

server.properties はBDSの起動フォルダーにある、名前=値のテキスト設定ファイルです。先頭の#はコメントです。サーバー名、ゲームモード、最大人数、接続用ポートなどを指定できます。

編集前にBDSを停止し、元ファイルのバックアップを残してください。メモ帳などのテキストエディターで編集し、設定を保存してからBDSを再起動します。ワールド作成時に保存される項目は、既存ワールドへ後から反映されない場合があります。

# 例：実際の環境に合わせて編集
server-name=Friends Bedrock
gamemode=survival
difficulty=normal
online-mode=true
allow-list=true
max-players=8
server-port=19132
view-distance=16
tick-distance=4

これは代表的な項目のみを抜粋した例です。既存ファイル内のその他の設定を削除せず、BDSのバージョンに合った書式を使ってください。

2. 最初に見るべき設定

項目意味・注意点
server-nameサーバー名。セミコロンは使えません。
gamemode / difficulty新規プレイヤー向けゲームモード、難易度。既存ワールドに対してはforce-gamemodeとの関係に注意。
online-mode=true公開サーバーでは有効を推奨。Xbox Live認証に関係します。
allow-list=trueallowlist.jsonに登録したプレイヤーへ参加を制限します。
max-players同時参加人数の上限。大きくすれば処理負荷も上がります。
server-port / server-portv6既定ではIPv4が19132、IPv6が19133。実際のネットワーク設定と一致させます。
level-name読み込むワールド名。worlds/フォルダー名との不一致に注意。
default-player-permission-level新規プレイヤーの権限。初期値はmemberです。

公式ドキュメントには、これ以外にもスクリプト、デバッグ、ネットワーク、ウォッチドッグの設定があります。値の制限は必ず使用中のBDSに同梱されたファイルとMicrosoft公式設定一覧を照合してください。

3. 友達限定サーバーの設定例

少人数のプライベートサーバーなら、次の組み合わせを出発点にできます。

online-mode=true
allow-list=true
max-players=8
default-player-permission-level=member
allow-cheats=false

allow-list=true だけでは参加者は登録されません。別ファイルの allowlist.json を用意し、現在のプレイヤー情報に合わせて管理してください。管理者権限を全員に付ける必要はありません。

注意：ワールドの安全性はこの5行だけで保証されません。ファイアウォール、公開するポート、管理者権限、バックアップも確認してください。

4. BDSが重いときの設定

まずはview-distance（表示範囲）とtick-distance（シミュレーションする範囲）、最大人数を確認します。

設定公式の許容範囲実用上の考え方
view-distance5以上の整数大きいほどチャンク処理の負荷が増えます。最初は控えめにして実測で調整。
tick-distance4〜12の整数大きいほど稼働するシミュレーション範囲が広がります。まず4で測定。
max-players正の整数参加人数上限に応じて負荷が増えるため、運用規模に合わせる。
max-threads使用BDSの説明を確認むやみに大きくせず、CPUと実測結果で判断。

これらを変更しても、アドオンの重いスクリプト、レッドストーンクロック、Mob密集などによる遅延は解消しないことがあります。変更は一度に1項目ずつ、同条件で比較すると原因を切り分けやすくなります。

5. 接続できない場合の確認

  1. BDSが正常に起動しているか、コンソールにエラーがないか確認します。
  2. 同じLAN内から接続できるかを先に試します。
  3. サーバーの接続先アドレスと使用ポートが一致しているか確認します。環境に応じてファイアウォールやルーター設定を確認します。
  4. enable-lan-visibility=trueは、カスタムポートを指定しても既定ポートへバインドする場合があります。複数BDSを同一マシンで動かす際は競合に注意してください。
  5. 最近のBedrock更新後の接続エラーは、NetherNet移行・Error 149ガイドも確認してください。

認証や通信に関する設定を無効化して回避するより、バージョンとネットワーク構成の整合性を確認する方が安全です。

6. allowlist.json・permissions.jsonを混同しない

server.propertiesのallow-listは「参加できる人を制限するか」の切り替えです。一方、allowlist.jsonは参加を許可する人の一覧です。

permissions.jsonは各プレイヤーの権限指定に使う別ファイルです。参加許可と操作権限は別の問題なので、「参加できる」だけのユーザーにoperator権限を与えないようにしてください。XUIDなどの識別子は現在のBDSと公式資料を確認したうえで扱い、未確認の推測値を自動入力しないことが重要です。

7. よくある失敗と解決の順番

設定を変えたのに反映されない

BDSを完全に停止してから編集・再起動したかを確認します。ワールド生成時の設定が既存ワールドへ適用されない場合もあります。

友達が誰でも参加できる

allow-listの値とallowlist.jsonの登録内容を確認します。設定ファイルの配置先を取り違えていないかも確認してください。

同じPCでBDSを二つ起動するとエラーになる

使用ポートの重複やenable-lan-visibilityの挙動を確認します。専用のポートを設定しても既定ポートとの競合が起きる場合があります。

公開IPや秘密情報を人に見せてしまった

ログや設定ファイルを相談時に共有する前に、IPアドレス、トークン、パスワード、個人情報を取り除いてください。
